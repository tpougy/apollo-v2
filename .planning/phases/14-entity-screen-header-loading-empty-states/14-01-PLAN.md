<objective>
Restructure `web/src/lib/entities/EntityScreen.svelte`'s list-view template (currently the bare
`<h2>` + text-only loading/empty states + unbounded `<Table>` at lines 382-460) into a proper
page-header row (title + description + right-aligned primary action, ENTTBL-04), a content-shaped
`Skeleton` loading state (ENTTBL-05), a composed `Empty` empty state that is a sibling to `<Table>`
rather than invalid content nested in `<tbody>` (ENTTBL-06), and a `Card`-bounded table container
(ENTTBL-07) — for all 9 entities across all 3 capability classes (full-CRUD, restricted, read-only),
since `EntityScreen.svelte` is the single generic component every entity shares. Because ENTTBL-04
requires a "short description" and no such field exists on `EntityConfig` today, this plan also adds
a new required `descricao: string` field to `EntityConfig` (`web/src/lib/entities/types.ts`) and
populates it once per entity in each of the 9 `web/src/lib/entities/defs/*.ts` files — a pure
config-data addition, not a business-logic change (`bun run check` enforces every def supplies it,
since it is required, not optional).

Purpose: This is the highest-blast-radius file in the v1.2 milestone — one change lands for all 9
entities simultaneously. This plan does the actual restructuring and proves it against a
representative full-CRUD entity (`fundos`) plus the existing all-9-entities nav regression
(`shell-nav.spec.ts`); Plan 14-02 (wave 2) adds dedicated new coverage proving the same restructuring
across the restricted and read-only capability classes, plus dual-color-scheme and full-suite
regression.
Output: `EntityScreen.svelte` restructured in place with a new `entity-header` row, a
`Skeleton`-based `entity-loading` state, an `Empty`-based `empty-state` (sibling to `<Table>`), and a
`Card`-bounded `entity-table-frame`; `EntityConfig.descricao` added and populated for all 9 entities;
`Skeleton`/`Empty` vendored via `bunx shadcn-svelte add`.
</objective>
