<objective>
Restyle `web/src/lib/auth/LoginScreen.svelte` so it reads as a properly composed, centered auth
`Card` — `CardHeader`/`CardTitle`/`CardDescription` at both the email-entry and code-entry steps,
full-viewport centering, and one consistent spacing scale (`space-y-4` field groups, `space-y-2`
label/control pairs) applied identically to both steps — per LOGIN-01/LOGIN-02 (REQUIREMENTS.md)
and ROADMAP.md Phase 12. The existing two-step magic-code auth flow (`enviarCodigo`,
`verificarCodigo`, `onSubmitEmail`, `onSubmitCode`, `reenviar`) and every load-bearing
`data-testid` stay behaviorally and structurally unchanged — this is a pure markup/class restyle,
proven live against the real InstantDB app, not mocked.

Purpose: This is the first phase of v1.2 ("Lapidação de UI") — the lowest-risk, single-file,
self-contained warm-up per ROADMAP's outside-in ordering (`LoginScreen` before `Shell` before
`EntityScreen`). It also establishes, for the very first time in this codebase, the two-tier
Tailwind spacing scale (`space-y-4`/`space-y-2`) that POLISH-04 (owned by Phase 17) will later
audit for consistency across the whole milestone.

Output: `LoginScreen.svelte` restyled in place with `Card` sub-parts already vendored in
`web/src/lib/components/ui/card/`; one new Playwright spec (`login-composition.spec.ts`) proving
Card composition, full-viewport centering, and spacing-scale parity at both steps; `playwright.config.ts`
updated to route the new spec correctly.
</objective>
