parallel and any edit there is a merge conflict.

Parent-existence rule: every `--*-id` link flag must be validated with `get_entity(etype=<parent>, eid=<id>)`
BEFORE transacting; `None` → JSON error `{"error": "parent_not_found", "etype": ..., "id": ...}` on

Querying links back (for tests): `client.query({"projetos": {"fundo": {}, "$": {"where": {"id": eid}}}})`
returns the row with a nested `fundo` object. This is the only way to prove a link was written.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI flags → transaction payload | Includes parent ids that become graph links |
| CLI process → InstantDB Cloud | Sole authorization authority; link targets are NOT existence-checked server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-14 | Tampering | `--fundo-id` / `--projeto-id` / `--etapa-id` pointing at a nonexistent or another user's record | mitigate | `get_entity(parent)` before every link write; a `None` result (which is also what another user's record looks like, since queries are perms-filtered) exits with `parent_not_found` — so a cross-user link attempt is rejected by the same code path |
| T-03-15 | Tampering | Optional flags written as explicit `null` | mitigate | `drop_none` applied to every payload; tests assert the key is absent when the flag is omitted |
| T-03-16 | Elevation of Privilege | A new entity module bypassing `crud_helpers` | mitigate | Grep gates per task plus the AST confinement test from 03-02 re-run in each task's acceptance criteria |
| T-03-17 | Input Validation (V5) | Malformed dates / out-of-vocabulary `tipoPrazo` reaching the database | mitigate | `validate_iso_date` callback and `click.Choice` reject at the CLI boundary with exit 2 before any network call |
</threat_model>
