InstantDB SDK facts VERIFIED against the installed `instantdb==1.0.63` source — do not re-derive:

- `Instant(app_id=..., admin_token=None)` **falls back to `os.environ["INSTANT_APP_ADMIN_TOKEN"]`** (`_sync/client.py:37-38`). Passing `admin_token=None` is therefore NOT safe. `session_client()` MUST pass `admin_token=""` — the constructor turns a falsy non-None value into `None` without consulting the environment.
- `client.as_user(token=...)` returns a clone that sends only the `as-token` header; the clone is constructed with `admin_token=""` when the parent had none, so the safety property survives cloning.
- `client.auth.send_magic_code(email) -> str` **returns the magic code itself**. Discard it. Printing it would make the CLI-01 email round trip meaningless and leak a credential.
- `client.auth.check_magic_code(email=..., code=...) -> tuple[dict, bool]` returns `(user, created)`; `user` has keys `id`, `email`, `refresh_token`.
- `client.auth.verify_token(token) -> dict` hits `/runtime/auth/verify_refresh_token` **unauthenticated** — no admin token, no impersonation header. This is the correct health check for `whoami`.
- Errors: `instantdb.InstantAPIError` (has `.status`, `.body`, `.hint`, `.trace_id`) subclasses `instantdb.InstantError`. Network failures surface as raw `httpx.HTTPError` subclasses and are NOT wrapped.

- `cli/apollo_cli/config.py` exports `load_instant_config() -> InstantConfig(app_id, env_file, admin_token_present)` and deliberately never exposes the admin token value. **Do not change that contract.** `instant_client._read_admin_token()` reads the value itself with `dotenv_values(config.env_file)[ "INSTANT_APP_ADMIN_TOKEN" ]` — never `load_dotenv`, never `os.environ`.
