InstantDB SDK facts VERIFIED against installed `instantdb==1.0.63` — do not re-derive:

- Build ops with `client.tx.<etype>[eid].create({...})` / `.update({...})` / `.delete()` / `.link({...})`, then `client.transact(chunk)`. Chunks compose: `.update({...}).link({...})` in one chain is one transact step list.
- New ids come from `from instantdb import id as new_id` — never `uuid.uuid4()` directly.
- `client.query({etype: {"$": {"where": {...}, "limit": N}}})` returns `{etype: [...]}`. A query the caller is not authorized for returns an EMPTY LIST with HTTP 200 — never an error (RESEARCH Pitfall 3). This is why the CLI-11 probe must be a write.
- `transact` is sent with `"throw-on-missing-attrs?": False`. A misspelled field name therefore attempts to mint a new attr, which `instant.perms.ts` denies via `attrs: { create: "false" }` — surfacing as a confusing `permission-denied`. Treat any `permission-denied` on a create that *should* be authorized as a field-name typo first.
- `update` on an id that does not exist behaves as an UPSERT and creates a partial record. `update_entity`/`delete_entity` MUST therefore call `get_entity` first and raise a not-found error when it returns `None`. This is an existence check, not an authorization check — the server remains the only authority on permissions.
- Errors: `instantdb.InstantAPIError` (`.status`, `.body`, `.hint`, `.trace_id`) ⊂ `instantdb.InstantError`; network failures are raw `httpx.HTTPError` subclasses.

**`cli/apollo_cli/crud_helpers.py`** — implement the `<interfaces>` contract.

`require_session()` calls `load_session()` and converts `MissingSessionError` into a JSON error on stderr (`{"error": "no_session", "hint": "run: apollo auth login --email <seu-email>"}`) followed by `SystemExit(EXIT_NO_SESSION)`; `CorruptSessionError` becomes `{"error": "corrupt_session", ...}` with the same exit code.

`client_for_session()` returns `(session_client(session), session)`.

`create_entity` generates `eid = new_id()`, builds `payload = drop_none(fields) | {"donoId": session.user_id}` — the `donoId` key is added AFTER the caller's fields so a caller cannot override it — chains `.link(links)` when `links` is non-empty, transacts, and returns `eid`. If `fields` already contains a `donoId` key, raise `ValueError` immediately: that is a programming error in a caller, and it must fail loudly at development time rather than being silently overwritten.

`update_entity` calls `get_entity` first; `None` → emit `{"error": "not_found", "etype": ..., "id": ...}` to stderr and `SystemExit(EXIT_API_ERROR)`. Then transacts `.update(drop_none(fields))` plus `.link(links)` when present. Never include `donoId` in an update payload.

`delete_entity` calls `get_entity` first with the same not-found handling, then transacts `.delete()`.

`get_entity` runs `client.query({etype: {"$": {"where": {"id": eid}}}})` and returns the single row or `None`.

`list_entities` runs `client.query({etype: {"$": {"where": where or {}, "limit": limit}}})` — omit `limit` from the `$` dict entirely when `None` rather than passing null — and returns the list.

All five data functions run inside one shared `@contextmanager instant_errors()` that maps `InstantAPIError` → JSON on stderr including `status`, `body.get("type")`, `body.get("message")`, `trace_id`, then `SystemExit(EXIT_API_ERROR)`; and `httpx.HTTPError` → `{"error": "network", "detail": str(exc)}` then `SystemExit(EXIT_NETWORK_ERROR)`. No retry logic anywhere — a comment must state why (non-idempotent creates; RESEARCH §Don't Hand-Roll).

`validate_iso_date` is a click callback enforcing `^\d{4}-\d{2}-\d{2}$` plus `datetime.date.fromisoformat`, raising `click.BadParameter` otherwise; returns the string unchanged (or `None`).
