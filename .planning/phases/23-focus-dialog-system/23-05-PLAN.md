pattern, but the one dialog that imports and calls a `derive.ts` export directly (`rotinasDoFundo`,
Plan 23-02) rather than receiving an already-filtered list, since that filter is a pure,
host-agnostic rule. Props: `open: boolean`, `fundoId: string`, `fundoNome: string`,
`instanciasRotina: { id: string; dataPrevista: string; tipoPrazo: string; template: { nome: string;
fundo: { id: string; nome: string } | null } | null }[]` (Dashboard.svelte's existing
`dadosNormalizados.instanciasRotina` shape already matches this structurally -- passing it directly
type-checks with zero cast, since TS structural typing accepts a variable with extra/matching
fields against this parameter type), `projetos: { id: string; nome: string; fundoId: string |
null }[]`, `tickets: { id: string; titulo: string; fundoId: string | null }[]`, `onOpenChange:
(open: boolean) => void`. No `breadcrumb` prop -- Fundo is never reachable as a second-level dialog
(only Projeto and Dia can ever open a second level, and neither's own body ever targets a fundo),
so this dialog is always depth-1 only; do not add an unused prop here.

Import `rotinasDoFundo` from `../derive`. Compute:
`const rotinas = $derived(rotinasDoFundo(instanciasRotina, fundoId));`
`const projetosVinculados = $derived(projetos.filter((p) => p.fundoId === fundoId));`
`const ticketsVinculados = $derived(tickets.filter((t) => t.fundoId === fundoId));`

Content (spec §4 row 5: todas as rotinas do fundo -- não só as da semana --, projetos e tickets
vinculados): title = `fundoNome`; contexto =
`` `${rotinas.length} rotinas · ${projetosVinculados.length} projetos · ${ticketsVinculados.length} tickets` ``.
Body: three `data-testid="fundo-dialog-rotinas"` / `"fundo-dialog-projetos"` /
`"fundo-dialog-tickets"` read-only lists (each a plain row, never a button -- Fundo is always a
leaf per depth-cap-2): rotinas show `instancia.template?.nome ?? "Rotina"` + `dataPrevista.slice(0,
10)`; projetos show `nome`; tickets show `titulo`. Each list renders "Nenhum(a) X vinculado(a)."
when empty. "editar" drives `fundosConfig`'s own hidden host (`fundo-dialog-edit-host`, `row-edit`
on `data-eid={fundoId}`). "ver na página completa" clicks `[data-testid="nav-fundos"]` then
`onOpenChange(false)`. `size="M"`.

`const fundoDialogProjetos = $derived(projetoRows().map((p) => ({ id: p.id, nome: p.nome, fundoId:

`const fundoDialogTickets = $derived(ticketRows().map((t) => ({ id: t.id, titulo: t.titulo,
fundoId: t.fundo?.id ?? null })));`
Import `FundoDialog`. Extend the dialog-stack chain with
`{:else if activeDialogRef?.kind === "fundo"}<FundoDialog open={true} fundoId={activeDialogRef.id}
fundoNome={fundoNomeFor(activeDialogRef.id)} instanciasRotina={dadosNormalizados.instanciasRotina}
projetos={fundoDialogProjetos} tickets={fundoDialogTickets} onOpenChange={(open) => { if (!open)
closeAllDialogs(); }} />`. Pass `onOpenFundo={openFundoDialog}` into the existing
`<RoutinesByFundo .../>` and `<ProjectStrips .../>` mounts, and `onOpenRotina={openRotinaDialog}`
(already defined in Plan 23-04) into `<RoutinesByFundo .../>`.

In `RoutinesByFundo.svelte`: add `onOpenFundo: (id: string) => void` and `onOpenRotina: (id:
string) => void` to `$props()`. On the existing `rotinas-fundo-titulo` button, add
`onclick={grupo.fundoId ? () => onOpenFundo(grupo.fundoId) : undefined}` -- when `grupo.fundoId` is

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-23-11 | Denial of Service | A null/empty fundo id reaching `openFundoDialog` and pushing a dialog ref that then resolves to nothing, rendering a confusing blank dialog | low | mitigate | `openFundoDialog` itself no-ops on falsy `id` (belt), and every call site also guards its own `onclick` (suspenders) -- two independent layers, per Task 2's action |
| T-23-12 | Information Disclosure | `rotinasDoFundo` exposing week-unbounded data the week-scoped `RoutinesByFundo` card deliberately does not show | low | accept | This is the documented, intended behavior of the Fundo dialog per spec-ui.md §4 row 5 ("não só as da semana") -- both views read the SAME already-owner-scoped array, this dialog simply applies a wider (not more privileged) date filter |
| T-23-13 | Tampering | `rotinas-row`'s `stopPropagation` accidentally omitted, causing a double-open (Rotina dialog stacked with Fundo dialog) | medium | mitigate | Task 3's e2e test (e) explicitly asserts only one `Dialog.Content` is ever visible after this click |
