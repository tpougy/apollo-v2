<objective>
Fix the two root causes that make `cli/` unable to run outside the `apollo-v2` monorepo: `bizdays.py`'s
module-level calendar load depends on `find_repo_root()` finding `shared/anbima-calendar.json` (breaks
the moment the package is copied into an isolated venv), and `config.py::load_instant_config()` requires
a reachable `.env.instantdb` to resolve `app_id` (raises before `dotenv_values()` is ever called, per
RESEARCH.md Pitfall 2 — not merely the "no app_id key" `ValueError` the requirement text implies).

Vendor `shared/anbima-calendar.json` into `cli/apollo_cli/data/`, read it via `importlib.resources`
instead of `find_repo_root()`, and give `config.py` an embedded default `app_id` as the last fallback
after explicit `env_file` / `APOLLO_ENV_FILE` / `.env.instantdb`. `apollo doctor` is updated to report
this provenance without touching the (unrelated, unchanged) admin-token diagnostic.

Purpose: make the CLI's two eager, monorepo-only filesystem lookups safe for a real `uv tool install`
outside the repo (PKG-01/PKG-03/PKG-04), and lock the calendar-vendoring invariant with a permanent
byte-parity test (PKG-02) — this plan is Phase 24's tracer: it proves the fix works end-to-end via a
real scratch-venv install/run-outside-repo round trip, not just unit tests in isolation.
Output: `cli/apollo_cli/data/anbima-calendar.json`, rewritten `bizdays.py`/`config.py`/`cli.py`, two new
regression test files, and a live-verified scratch install proving `apollo --version`/`doctor`/`fundo
listar` all survive running from outside `apollo-v2` with no `shared/`/`.env.instantdb` present.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Distributed wheel ↔ end-user machine | Code and the new `_DEFAULT_APP_ID` constant ship inside a build artifact anyone can `uv build`/inspect (unpack the wheel, `strings`, decompile) — nothing in it may be secret. |
| CLI process ↔ local filesystem (`.env.instantdb`/`APOLLO_ENV_FILE`) | Local, trusted-by-default env file read via `dotenv_values`; not attacker-controlled in this single-user threat model, but a silently-swallowed lookup failure must degrade to a known-safe default, never to an unrelated file. |
| CLI process ↔ InstantDB backend | Governed entirely by `instant.perms.ts` server-side rules; `app_id` alone identifies which app to query and grants no bypass of those rules. |
