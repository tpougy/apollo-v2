## Encadeado semantics — the recorded decision, not an assumption

RESEARCH.md Assumption A2 and Open Question 1 flag encadeado as the phase's single
largest interpretive leap and ask the planner to resolve it explicitly. Resolved here,
consistent with 05-01's D-05-B:

**D-05-B (restated).** `offsetDias` on an `encadeado` template counts **business days**
after the antecessor instance's `dataPrevista`, via `addBusinessDays` over the vendored
ANBIMA calendar. Rationale in 05-01. Calendar-day chaining is deliberately not supported
and would require a future `tipoOffset` discriminator rather than a reinterpretation of
this field.

**D-05-D — competencia is INHERITED from the antecessor instance.** An encadeado
instance's `competencia` is copied verbatim from the antecessor instance it chains off,
and its own `regraCompetencia` is not consulted. Rationale: CONTEXT.md's reference note
defines the chain relationship as "the antecessor template's own instance **for the same
competência**". If each side derived competencia independently from its own rule and its
own `dataPrevista`, a chain crossing a month boundary would pair instances from different
competências and the phrase "same competência" would become unenforceable. Inheriting
makes the pairing definitional. Consequence, and it is intentional: an encadeado template
with `regraCompetencia: "manual"` still generates, because that field is simply not part
of its date derivation. Document this in the module docstring and in the CLI `--help`
text touched by 05-05.

**D-05-E — `dataPrevistaEstimada` marks a not-yet-final date.** Set it (to the same value
as `dataPrevista`) when the antecessor's instance for that competencia is EITHER not yet
persisted (it is being computed in this same run) OR persisted with `status !== "concluida"`.
Omit it when the antecessor's instance exists and reads `concluida`. This is the only
encadeado-specific behavior in scope; `propagarAtrasoSoft` is stored and never acted upon
(PROJECT.md C-09).

**D-05-F — the antecessor's own `dataPrevista` is used even when the antecessor is late.**
Delay propagation (recomputing a successor because its antecessor slipped) is explicitly
out of scope per C-09. The chain is dated from the antecessor's *planned* date, and
`dataPrevistaEstimada` is the flag that says "this is provisional". Critically, this keeps
the encadeado `dedupeKey` stable across runs: a key derived from a moving date would
generate a fresh record on every job run and destroy idempotency.
</context>
