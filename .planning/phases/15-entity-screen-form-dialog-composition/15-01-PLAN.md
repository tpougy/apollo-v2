<objective>
Restructure the create/edit `Dialog` form inside `web/src/lib/entities/EntityScreen.svelte` (currently a
flat, unspaced sequence of bare `<div>`s ending in two trailing `<Button>`s with no busy state, per
15-PATTERNS.md's exact structure) so it reads as a properly composed form: a consistent `space-y-4`/
`space-y-2` field-spacing scale across every field/link/xorLink wrapper (ENTFRM-05), a `Dialog.Description`

state matching `LoginScreen.svelte`'s already-proven `ocupado`/`LoaderCircle` pattern (ENTFRM-07), and a
required-field visual indicator driven by `config.fields[].required` (ENTFRM-08) — for all 9 entities
across all 3 capability classes, since `EntityScreen.svelte` is the one generic component every entity
shares. Per CONTEXT.md's explicit fallback clause, this plan uses the plain-utility-class spacing pattern
(`space-y-4`/`space-y-2`, identical to `LoginScreen.svelte`'s own scale) rather than installing the new
`Field`/`FieldGroup` shadcn-svelte primitive — the codebase's own render block has 8 distinct branches
(6 field kinds + links + xorLink) and no field currently carries separate helper/description text
(`FieldDef` has no such property), so the utility-class fallback delivers the identical visual outcome
with a smaller, lower-risk diff to the milestone's highest-blast-radius file.

code Phase 14 just landed is untouched.

entities from all 3 capability classes.
