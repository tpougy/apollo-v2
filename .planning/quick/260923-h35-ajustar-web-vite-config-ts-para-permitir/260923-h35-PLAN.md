<objective>
Make `web/vite.config.ts` resolve the InstantDB `app_id` on Cloudflare Pages, where the gitignored `.env.instantdb` file never exists on disk and today's `readFileSync` unconditionally throws, breaking the build. Add a fallback that reads `process.env.VITE_INSTANT_APP_ID` (a real env var configurable in the Cloudflare Pages dashboard) only when the file is absent. Local dev, where the file is present, must behave exactly as it does today — same parse path, same extracted value, same throw-if-missing guard. The admin token's handling is completely out of scope and must not change: it continues to be read exclusively from the parsed file, never from `process.env`, never injected into the client bundle.

Purpose: the app currently cannot build in Cloudflare Pages at all, because the only source of `app_id` is a file that is deliberately gitignored (it also holds `INSTANT_APP_ADMIN_TOKEN`) and therefore never present in that build environment.
Output: `web/vite.config.ts` with an `existsSync`-gated fallback; a live build proof that all three scenarios (file present, file absent + env var present, file absent + env var absent) behave correctly.
</objective>
