<objective>
Replace `apollo auth login`'s magic-code send/verify transport: stop calling `client.auth.send_magic_code`/
`check_magic_code` from the `instantdb` Admin SDK (which hits admin-only `/admin/*` endpoints and therefore
requires `INSTANT_APP_ADMIN_TOKEN`), and instead call InstantDB's public `POST {api_uri}/runtime/auth/
send_magic_code` / `POST {api_uri}/runtime/auth/verify_magic_code` directly via `httpx` — endpoints
confirmed (RESEARCH.md, server-source-verified) to run the exact same business logic and error-formatting
middleware as their admin counterparts, just without an authorization requirement. `apollo auth login`'s
observable JSON/exit-code contract does not change; only the internal transport does (CONTEXT.md decisions
1-2, AUTH-01/AUTH-02).

`login_client()` in `instant_client.py` is NOT deleted — `cli/tests/test_cross_user_isolation.py`'s
admin-only `delete_user` teardown (line 367) has no public-endpoint equivalent and is its one legitimate
remaining caller (RESEARCH.md Pitfall 1, overriding CONTEXT.md decision 3's literal "if nothing else calls
it, remove it" framing, which predates that finding). Its docstring is corrected instead, and
`test_auth_rejection.py`'s AST-walk gate is tightened to prove `auth.py` no longer calls it at all
(CONTEXT.md decisions 3/6, AUTH-05).

Purpose: eliminate `apollo auth login`'s only remaining dependency on `INSTANT_APP_ADMIN_TOKEN`, without
changing anything a caller of `apollo auth login` can observe, and without silently narrowing the request
timeout (RESEARCH.md Pitfall 2) or silently loosening the structural gates that keep the admin token
confined (RESEARCH.md Pitfall 1).
Output: rewritten `auth.py`/`instant_client.py`, an explicit `httpx` dependency, a corrected `README.md`,
a tightened `test_auth_rejection.py` AST-walk gate plus a new network-error test, and a new permanent live
test proving the invalid-code error path works end-to-end with zero admin token present — this plan's
tracer task IS that live proof, run against the real InstantDB API.
</objective>
