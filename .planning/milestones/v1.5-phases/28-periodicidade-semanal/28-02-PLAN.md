## Naming deviation from PATTERNS.md, deliberate (read before Task 1)

PATTERNS.md/RESEARCH.md sketch the weekly-enumeration helper as a private,
underscore-prefixed function (`_weekly_occurrences`/local unexported `weeklyOccurrences`),
mirroring `_compute_fixed_instances`. This plan makes it **public** instead:
`weekly_occurrences` (Python, no leading underscore) and an **exported** `weeklyOccurrences`
(TypeScript) — matching the existing convention for every OTHER directly fixture-tested
day-math primitive in this module (`nth_business_day_of_month`/`nthBusinessDayOfMonth`,
`nth_calendar_day_of_month`/`nthCalendarDayOfMonth`, `end_of_next_month`/`endOfNextMonth`,
`shift_competencia`/`shiftCompetencia` — all public, all imported directly by
`cli/tests/test_routine_job.py` and `web/src/lib/routineJob.test.ts` for parametrized
`dayMath`-fixture testing). `_compute_semanal_instances`/`computeSemanalInstances` themselves
(the template-level orchestration, mirroring `_compute_fixed_instances`) stay private/local,
exactly as PATTERNS.md specifies — only the pure date-math primitive underneath is made public,
for direct `dayMath.weeklyOccurrences` fixture testing (Task 2).

<assumption_delta_decision>
## Assumption Delta: `tipoGeracao` gains a 4th variant (add-alongside, not promote)

**decision: add-alongside**

This phase extends `tipoGeracao`'s variant set from 3 (`du_fixo`, `corrido_fixo`, `encadeado`)
to 4 (+ `semanal`) — a pluralization-shaped change to an existing discriminated-union-like
field. Per the checkpoint: the new `semanal` type is added ALONGSIDE the existing three, each
still dispatched via its own `elif`/`else if` branch and its own compute function
(`_compute_semanal_instances`/`computeSemanalInstances`, a new SIBLING of
`_compute_fixed_instances`, never a modification of it). This is explicitly NOT a "promote" —
there is no single, more-general representation that subsumes both month-anchored
(`du_fixo`/`corrido_fixo`, "the Nth day of THIS candidate month") and week-anchored (`semanal`,
"every occurrence of weekday X across the WHOLE date range") dating: the two use genuinely
different candidate-generation loops. `_compute_fixed_instances` iterates a fixed 2-element
`candidate_months` list and computes exactly one date per month via `nth_day_fn`;
`weekly_occurrences` walks a date cursor in +7-day steps until it exhausts an arbitrary-length
date range, producing a variable count (7 in the real Aug/Sep-2026 case, not "1 per month").
Forcing `semanal` through `_compute_fixed_instances`'s month-candidate shape would require
rewriting that helper's core loop for every existing caller (`du_fixo`, `corrido_fixo`) — a
change CONTEXT.md's own `<code_context>` section and RESEARCH.md's "Pattern 1" both
independently already ruled out before this plan was written. `du_fixo`/`corrido_fixo`/
`encadeado`'s own dispatch branches, compute functions, and validation are untouched by this
phase (CONTEXT.md decision #7; this plan's own `must_haves.prohibitions` enforce it).
</assumption_delta_decision>
