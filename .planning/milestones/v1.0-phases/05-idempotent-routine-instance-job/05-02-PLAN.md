## Algorithm specification (the single documented algorithm both runtimes implement)

1. **Range.** `rangeStart = today`; `rangeEnd = endOfNextMonth(today)`. Only two
   calendar months can ever contain a date in that range: `month(today)` and the
   following month. Evaluate exactly those two candidate months per template.
2. **`du_fixo`.** For each candidate month `(y, m)`:
   `dataPrevista = nthBusinessDayOfMonth(y, m, offsetDias)`.
   `nthBusinessDayOfMonth` is composed from Phase 2's primitives per RESEARCH Pattern 2:
   let `day1 = y-m-01`; `first = isBusinessDay(day1) ? day1 : addBusinessDays(day1, 1)`;
   return `n <= 1 ? first : addBusinessDays(first, n - 1)`. This composition is correct
   ONLY because `addBusinessDays` has strictly-after semantics — that is exactly why the
   `isBusinessDay(day1)` branch exists and must not be "simplified away".
3. **`corrido_fixo`.** Reserved for 05-04; `nthCalendarDayOfMonth` ships here (with tests)
   so the day-math surface is complete and cross-validated in one place.
4. **`encadeado`.** Reserved for 05-04. In THIS plan a template with
   `tipoGeracao === "encadeado"` is skipped with `tipo_geracao_desconhecido`; 05-04
   replaces that branch. This is deliberate tracer sequencing, not an omission — see
   the phase's TRACER ordering.
5. **Competencia.** `competencia = shiftCompetencia(dataPrevista, regraCompetencia)`,
   which trims the input and shifts the month of `dataPrevista` by 0 / -1 / -2 / +1 for
   `M0` / `M-1` / `M-2` / `M+1`, formatted `YYYY-MM`. Any other value — including
   `"manual"`, a typo, or a trailing space that survives trimming — returns `null` and
   the template is skipped with `regra_competencia_nao_suportada` (RESEARCH Pitfall 3;
   CONTEXT.md leaves this to the planner and this is the recorded choice: **`manual`
   means "no auto-generation for this template"**, never a guessed default).
6. **Offset validation.** `offsetDias` absent/null → `offset_dias_ausente`.
   Present but not an integer, or `< 1` for `du_fixo`/`corrido_fixo`, or `< 0` for
   `encadeado` → `offset_dias_invalido`. Never throws.
7. **Filter.** Keep only `rangeStart <= dataPrevista <= rangeEnd` (plain ISO string
   comparison is correct — all dates are zero-padded).
8. **dedupeKey.** `` `${templateId}:${competencia}:${dataPrevista}` `` — plain
   concatenation, NOT a cryptographic hash (RESEARCH Assumption A5). The uniqueness
   guarantee lives in `instanciasRotina.dedupeKey.unique()`, not in the key's entropy;
   concatenation is human-debuggable in `apollo rotina instancia listar` output and
   removes any TS/Python hash-output drift risk.
9. **Per-template isolation.** A template that throws during its own computation is
   caught, recorded in `skipped`, and never aborts the other templates
   (RESEARCH Pitfall 4).
10. **Determinism.** `expected` sorted ascending by `dedupeKey`; `skipped` sorted
    ascending by `(templateId, reason)`. Required for byte-stable cross-runtime fixture
    comparison.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `templatesRotina` row → compute core | Free-text `tipoGeracao`/`regraCompetencia` and an unvalidated numeric `offsetDias` cross from storage into date arithmetic |
| compute core → (later) InstantDB writes | Every value this module returns becomes a persisted record in 05-03; a wrong `dedupeKey` here permanently breaks idempotency |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05 | Denial of Service | `computeExpectedInstances` | mitigate | Per-template try/catch converts any throw into a `skipped` entry; Task 3 pins this with a scenario where a `CalendarRangeError`-throwing template coexists with a healthy one |
| T-05-14 | Input Validation (ASVS V5) | `regraCompetencia` free text | mitigate | Explicit allowlist `REGRAS_COMPETENCIA_SUPORTADAS` with a `null` default branch; `"manual"`, typos, and whitespace variants all skip with `regra_competencia_nao_suportada` rather than defaulting to `M0` |
| T-05-15 | Input Validation (ASVS V5) | `offsetDias` numeric input | mitigate | Integer + per-`tipoGeracao` range check before any date arithmetic; invalid values yield `offset_dias_invalido`, never an `undefined` propagating into `addBusinessDays` |
