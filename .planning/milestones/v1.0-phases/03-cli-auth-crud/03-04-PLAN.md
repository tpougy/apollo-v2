<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI flags → transaction payload | Includes ticket bodies containing real third-party email content |
| CLI process → InstantDB Cloud | Sole authorization authority; link targets are NOT existence-checked server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-18 | Tampering | Subtarefa created with zero or two parents | mitigate | Explicit XOR count check raising `click.UsageError` before any network call; tested in both directions |
| T-03-19 | Tampering | `--concluida` flag pair defaulting to `False` on `editar`, silently un-completing work | mitigate | Flag pair declared `default=None` on `editar`; a dedicated regression test edits only `--titulo` and asserts `concluida` is unchanged |
| T-03-20 | Tampering | Link written to a nonexistent or another user's parent | mitigate | `get_entity(parent)` before every link write; perms-filtered queries make another user's record indistinguishable from nonexistent, so both are rejected identically |
| T-03-21 | Information Disclosure | Ticket `corpo` (third-party email content) leaking into logs/errors | mitigate | Error payloads carry only `etype`/`id`/InstantDB error fields, never the record body; no logging framework is introduced in this phase |
| T-03-22 | Elevation of Privilege | New entity modules bypassing `crud_helpers` | mitigate | Per-task grep gates plus the AST confinement test from 03-02 re-run in Task 2's acceptance criteria |
</threat_model>
