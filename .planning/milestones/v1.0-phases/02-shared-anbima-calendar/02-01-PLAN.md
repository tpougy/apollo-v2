<objective>
Vendor the ANBIMA holiday table as `shared/anbima-calendar.json` and create the only sanctioned path to regenerate it (`shared/scripts/update_calendar.py`), then lock the vendored file's shape and content with an automated structural gate.

Purpose: Every business-day answer in Apollo v2 — on both the SPA and the CLI — is derived from this one file. If it is wrong, truncated, or silently regenerated from a different source, the system quietly miscalculates regulatory deadlines for fund controladoria. This plan makes the data correct, provably static, and provably regenerable.
Output: `shared/anbima-calendar.json`, `shared/scripts/update_calendar.py`, a `cli/tests/` pytest package, and `test_calendar_json.py` as the CAL-01 gate.
</objective>

<environment_facts>
Verified during research (2026-08-09) and re-verified against the repo at plan time:

- `bizdays` PyPI latest is `1.0.19` (MIT, `wilsonfreitas/python-bizdays`). Its wheel bundles a plain-text calendar file `ANBIMA.cal` as package data.
- `ANBIMA.cal` format: the first lines are weekday-exclusion names (`Saturday`, `Sunday`), followed by one ISO date per line. Current content spans `2000-01-01` through `2099-12-25` (1276 dates). Filtering to `<= 2078-12-31` yields ~1003 dates — **NOT** the "~948" figure quoted in PROJECT.md C-03, which is a stale number carried over from an older `bizdays` release's documentation page. C-03's *date range* (2000-2078) is authoritative; its *count* is descriptive and stale. Do not hardcode 948 anywhere.
- `github.com/ianliu/feriados-anbima` (the repo named in C-03) is **not** a static table — it is a 25-line GPLv3 script that downloads an `.xls` from ANBIMA's website at runtime. It ships no data file. It is therefore unusable as a vendoring source without violating C-03's "never at runtime" rule, and its GPLv3 license makes redistributing its code undesirable. The `bizdays` package's bundled `ANBIMA.cal` is the same official data, already static, MIT-licensed, and already a dependency of this phase.
- `cli/` is a `uv`-managed flat-layout package (`[tool.uv.build-backend] module-root = ""`). Quality gates today: `cd cli && uv run ruff check . && uv run ruff format --check . && uv run ty check`, all zero-finding, with `extend-select = ["I", "ANN"]` (every function needs full annotations, imports must be sorted).
- `cli/apollo_cli/config.py` already exports `find_repo_root()`, which walks upward from `Path(__file__)` until it finds a directory containing `.env.instantdb`. Reuse it — do not write a second repo-root discovery.
- `cli/` has no test framework installed yet and no `cli/tests/` directory.
- `biome.json`'s `files.includes` is `["shared/**/*.ts", "web/src/**/*.ts", "web/src/**/*.svelte", "web/vite.config.ts"]` — it does **not** cover `.json` or `.py` under `shared/`. This is deliberate and stays unchanged: the vendored calendar is generated data whose formatting is owned by the generator, not by Biome.
</environment_facts>

Its module docstring MUST state, in its first paragraph: that it is a manual, human-invoked, offline regeneration path run roughly yearly; that it is NEVER imported or invoked by `cli/apollo_cli/**` or `web/src/**`; that it performs no network access; and that the one-line change to widen the vendored range beyond 2078 is the `DEFAULT_END` constant.

Module-level `Final` constants: `DEFAULT_START = "2000-01-01"`, `DEFAULT_END = "2078-12-31"`, `MIN_EXPECTED = 900`, `MAX_EXPECTED = 1200`, `WEEKDAY_NAMES = frozenset({"Monday","Tuesday","Wednesday","Thursday","Friday","Saturday","Sunday"})`, `ISO_DATE_RE = re.compile(r"^\d{4}-\d{2}-\d{2}$")`.

Functions (exact names and signatures — plan 02-03's gates reference them):

- `def read_anbima_cal() -> list[str]:` — locate the bundled calendar via `importlib.resources.files("bizdays").joinpath("ANBIMA.cal")` and return its `read_text(encoding="utf-8").splitlines()`. Raise `FileNotFoundError` with a message naming the expected resource if it is absent. No network access, no fallback to any other source.
- `def extract_holidays(lines: list[str], start: str, end: str) -> list[str]:` — strip each line; drop empty lines; drop lines in `WEEKDAY_NAMES`; raise `ValueError` naming the offending line for anything else that does not match `ISO_DATE_RE`; keep dates where `start <= d <= end` (plain string comparison is correct for zero-padded ISO); return `sorted(set(kept))`.
- `def build_payload(holidays: list[str]) -> dict[str, object]:` — return a dict with keys in this exact order: `source` (the literal string `"bizdays PyPI package (MIT, wilsonfreitas/python-bizdays) bundled ANBIMA.cal"`), `sourceVersion` (resolved at runtime via `importlib.metadata.version("bizdays")`, not hardcoded), `generatedBy` (`"shared/scripts/update_calendar.py"`), `note` (a one-sentence string stating the file is vendored static data, never computed at runtime, regenerate with the command above), `start` (`holidays[0]`), `end` (`holidays[-1]`), `count` (`len(holidays)`), `holidays`. Raise `ValueError` if `holidays` is empty.
- `def serialize(payload: dict[str, object]) -> str:` — `json.dumps(payload, indent=2, ensure_ascii=False)` plus a single trailing newline. This exact serialization is the byte-idempotence contract; nothing else may write this file.
- `def main(argv: list[str] | None = None) -> int:` — `argparse` with `--out` (default: `find_repo_root()`-independent — resolve as `Path(__file__).resolve().parents[1] / "anbima-calendar.json"`, i.e. `shared/anbima-calendar.json`), `--start` (default `DEFAULT_START`), `--end` (default `DEFAULT_END`), and `--check` (flag: regenerate in memory, compare to the on-disk file's exact bytes, print a diff summary, write nothing, return 0 on identical / 1 on different or missing). Sanity guard before any write: if `not MIN_EXPECTED <= count <= MAX_EXPECTED`, print an error naming the actual count and return 1 **without touching the output file**. On success print the output path, the count, and the resolved `start`/`end`, and return 0. Guard the entrypoint with `if __name__ == "__main__": raise SystemExit(main())`.

Every function fully annotated (ruff `ANN` is on); imports sorted (ruff `I`); lines <= 100 chars.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `bizdays` package data → `update_calendar.py` | Third-party package content crosses into a committed repo artifact. Mitigated by the sanity band, the shape assertions in Task 2, and the fact that the file is reviewed in a diff before commit. |
| `shared/anbima-calendar.json` → both runtimes | Committed static data crosses into every date computation in the product. This is a *correctness/compliance* boundary, not a classic security one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering (data integrity) | `shared/anbima-calendar.json` | mitigate | `test_calendar_json.py` asserts shape, ordering, uniqueness, exact boundaries, a 24-date federal-holiday spot-check, and a municipal-holiday-absence check. A silently corrupted or substituted table fails the suite. This is flagged as a **compliance risk, not merely a bug**: a wrong holiday in a fund-controladoria system produces a wrong regulatory deadline. |
| T-02-02 | Tampering (supply chain) | `update_calendar.py` | mitigate | The generator has no network path at all (asserted by grep gate), reads only from the locally installed MIT-licensed `bizdays` package, and refuses to write outside the [900, 1200] sanity band. Any future `--fetch` mode is explicitly out of scope for this phase. |
| T-02-03 | Denial of service (silent) | `update_calendar.py` write path | mitigate | Sanity band + `--check` mode mean a bad run leaves the previously-good committed file untouched rather than replacing it with an empty/truncated table. |
| T-02-04 | Information disclosure | — | accept | The vendored calendar is public, non-sensitive data; the generator handles no credentials and never reads `.env.instantdb`. |
| T-02-05 | Elevation of privilege | — | accept | No auth, no network, no user input surface in this plan. |

**Canon-referral (dropped, not minted):** path-traversal hardening on the `--out` argument is canon input-validation for a developer-only, human-invoked local script with no untrusted caller — noted and dropped.
</threat_model>
