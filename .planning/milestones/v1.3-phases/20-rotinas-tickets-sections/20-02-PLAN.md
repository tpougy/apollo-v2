Create `RotinasSection.svelte`: resolve `instanciasRotinaConfig`/`templatesRotinaConfig` via
`configByEtype`, each guarded by a `requireConfig` throw-check (mirror
`ProjetosSection.svelte`'s own helper). Local `activeTab = $state<"instancias" | "templates">("instancias")`.
Render `Tabs.Root value={activeTab} onValueChange={(v) => { if (v) activeTab = v as "instancias" | "templates"; }}`
with `Tabs.List` containing two `Tabs.Trigger`s: `data-testid="rotinas-tab-instancias"` (label
"Instâncias") and `data-testid="rotinas-tab-templates"` (label "Templates") — mirror
`ProjetosSection.svelte:361-372`'s identical `Tabs.Root`/`Tabs.List` usage.

Do NOT wrap the whole component in a top-level `<h2>` — `EXPECTED_H2_BY_TESTID["nav-instanciasRotina"]`
in `shell-nav.spec.ts:23` expects the page's SOLE `<h2>` to read "Instâncias de rotina", which is
`instanciasRotinaConfig.titulo`, supplied by `EntityScreen`'s own header. Adding a second
`RotinasSection`-level heading would break that strict single-`<h2>` assertion the moment both
tabs' content mount.

`Tabs.Content value="instancias"` must guard its `EntityScreen(instanciasRotinaConfig)` mount
behind `{#if activeTab === "instancias"}`, and `Tabs.Content value="templates"` must guard its
content (a `<p>` reading "Configuração que gera as instâncias." above
`EntityScreen(templatesRotinaConfig)`) behind `{#if activeTab === "templates"}` — bits-ui's
installed `Tabs.Content` mounts BOTH tabs' children immediately (setting a `hidden` attribute on
the inactive one, never unmounting), so without this guard BOTH `EntityScreen` instances would
render their own `<h2>` simultaneously on first load, breaking the exact single-`<h2>` assertion
above. This is the same fix `ProjetosSection.svelte`'s "Todas as tarefas" tab already needed and
documents at length (`ProjetosSection.svelte:588-601`) — apply it to BOTH tabs here since both
mount an `EntityScreen` directly, unlike `ProjetosSection`'s own default "detalhe" tab which does
not.

Neither `EntityScreen` mount takes any new prop — `capabilities.create`/`.delete` on
`instanciasRotinaConfig` stay `false` exactly as declared in `defs/instanciasRotina.ts`, zero new
affordance.

In `Shell.svelte`, import `RotinasSection` and add a branch mounting it for
`rota.etype === "instanciasRotina"`, `{#key rota.etype}`-wrapped, inserted alongside the existing
`rota.etype === "tickets"`/`"projetos"` branches, ahead of the generic `{:else}` fallback.

Create `web/e2e/rotinas-section.spec.ts`: one test asserting (a) `nav-instanciasRotina` lands on
the Instâncias tab by default with `page.locator("h2")` reading "Instâncias de rotina" with count
1, (b) `entity-create-start` and `row-delete` both have count 0 on that tab (no create/delete
affordance), (c) clicking `rotinas-tab-templates` switches `page.locator("h2")` to "Templates de
rotina" (count 1) and shows a visible paragraph containing "configuração que gera as instâncias".
